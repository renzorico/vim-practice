Read `docs/briefs/phase-b/_common.md` first. The contracts are already changed on this branch: read the diff of `packages/engine/src/types.ts` (`TextEdit`, `StepResult.edits`, `Snapshot.edits`) and `packages/world/src/types.ts` rule 3.

## Why
World 2 lets the player edit the field: `x` a rock, `dd` a wall row, `u` it back. Today the sim guesses which cell changed by diffing texts around the cursor. Inside a run of equal tiles the guess is wrong for undo, redo, `X`, `dh`, `db`, `a`, `A`, charwise `p` and linewise edits off column 0, so the wrong Blot dies or survives. The engine knows exactly what it changed; it must say so.

## 1. Engine: report edits
- Every place that changes `lines` records `TextEdit`s (offsets in `lines.join('\n')`, see the contract). Find the one or two buffer-writing helpers and record there, rather than in every operator.
- `StepResult.edits`: the edits this key made, in order. Exact and minimal: only characters really removed or put in. A replace (`r`, `R`, `~`, `gu`, `gU`) is one edit per replaced run, with `removed === inserted.length`. `J` is not a replace: it removes a newline and maybe spaces.
- Linewise: `dd` on row L removes row L's characters plus the '\n' after it (the last row: the '\n' before it). `o`/`O`/`p`/`P` linewise insert whole rows with their '\n'. Pick one convention per command, document it in a comment, test it.
- Undo history: `Snapshot.edits` collects the change's edits while it is in progress (an insert session: one per key, `<BS>` included). `u` reports the inverses of the top entry's edits, last first, at their real positions; `<C-r>` reports the redo entry's edits again. `.` reports the edits it makes, like any change. `:s`, `:d`, `:normal`, macros (if supported) likewise.
- No text change: `edits` is `[]` (motions, errors, `not-allowed`, a no-op `x` on an empty line).

## 2. World sim: use them
- `packages/world/src/sim/remap.ts`: replace `changedSpan` and the anchor with a function that carries an offset through a list of edits (rule 3 a/b/c). Delete `changedSpan`, the `anchor` parameters and every caller's anchor argument. `fixedChanged` uses the same mapping.
- Player commands: `changeBuffer` takes the step's `edits`. Effects and entities build their own (`set-rows`: one edit per row; `delete-row`: the row plus the '\n' after it, or before it for the last row). Nothing compares texts to find a change any more (comparing to decide "did it change at all" is fine).
- `rows-changed` `fromLine`/`toLine`: old-text lines from the earliest edit start to the latest edit end, carried back to old offsets.

## 3. Tests (the point of this task)
- Property test in the engine: for every existing golden case and every key step, applying `edits` to the old text gives the new text. Add this to the golden runner so every future golden case checks it too.
- Exactness, in runs of equal tiles (`"ooooo"` and two rows `"ooo"`,`"ooo"`): `x` at col 2; `X` at col 3; `dh`, `db`, `a`+text+`<Esc>`, `A`, charwise `p`, `dd` at col 3, `J`, `r`, `3x`, `u` and `<C-r>` after each; `.` repeats. Each asserts the exact `TextEdit` list.
- World sim, same runs, Blots on cells 1 and 3: each command removes or shifts exactly the right Blot; `u` never brings one back; a `r` under a Blot on a walkable result keeps it; a fixed tile inside the run cancels `x` on itself but not on a neighbour.
- All existing tests stay green (1798 today). Every stage's `stageReplayIssue` still passes.
