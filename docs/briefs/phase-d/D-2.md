## 1. Engine: `<C-d>` and `<C-u>`
Measured in Neovim 0.11 (`nvim --headless --clean`, `set lines=30`, so the window is 28 rows and 'scroll' defaults to 14):
- 100 lines, cursor (1,6) on equal-length rows: `<C-d>` -> (15,6); again -> (29,6); `5<C-d>` -> (6,6) and 'scroll' is now 5; `5<C-d><C-d>` -> (11,6). `<C-d><C-u>` -> back to (1,6). `<C-u>` from (50,7) -> (36,7).
- 30 lines, cursor line 25: `<C-d>` -> line 30 (clamped). 10 lines, line 1: `<C-d>` -> line 10. On the last line: no move (Vim beeps: report an error, so the world bumps). `<C-u>` on line 1: no move, error.
- Ragged rows: the column did not simply follow `desiredCol` (from (1,6), lines of length 3..7: (15,2), then (29,3)). Find Neovim's rule with golden cases and match it exactly.
Implement both with counts (the count sets `scroll` first, and it stays). `scroll` 0 means `floor(windowHeight / 2)`; `windowHeight` defaults to 28. `init` sets `scroll: 0`. They are not operator motions (`d<C-d>` is an error in Neovim; check it). Undo-neutral, `.`-neutral.
Golden runner: set `lines=30` (window 28) for every case, so existing cases do not change, and add at least 12 cases covering the above (counts, clamping, ragged columns, `<C-u>`, `d<C-d>`).

## 2. World sim
- `Stage.windowHeight` goes to the engine as `windowHeight` on every player step (schema: optional positive integer).
- `Legend.emptyRow`: where a row is empty, the cell (line, 0) is that tile; there are no other cells on the row. Use it everywhere a tile is read (`blocked`, `nearestFreeCell`, entity movement, landing checks, walking paths through an empty row). Without `emptyRow`, behaviour is unchanged (all existing tests stay green).
- `<C-d>`/`<C-u>` are jumps: only the landing cell is checked, like `G` or `}`.
- Tests: `}` lands on an empty row with `emptyRow` walkable; bumps without it; `j` through an empty row passes at column 0 and the next `j` comes back to column 0 too (Vim: `}` sets the wanted column to 0; `j` from an empty row keeps the old wanted column, check both); a Blot can chase onto an empty-row cell; `dd` on an empty row removes it and remaps entities below; `<C-d>` respects `Stage.windowHeight` (a stage with windowHeight 10 moves 5).

## 3. Solver
Add `<C-d>`/`<C-u>` (counts 1..rows) and make the identity include `engine.scroll` (it changes later moves). `{`/`}` are already there; check they now find routes through clearings in a tiny stage with `emptyRow`.

## 4. Linter and scene
- Linter: a legend's `emptyRow` follows the same tile rules as other tiles; a stage with empty rows and no `emptyRow` gets a warning (those rows are unreachable).
- Scene: draw an empty row's (line, 0) cell with the `emptyRow` sprite; the rest of the row, inside the map's bounding box, uses the existing pale "unwritten" look.
