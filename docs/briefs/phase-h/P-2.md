## The gaps (goldens provided, generated with Neovim)
`tools/golden/cases/undo-parity.json` holds 14 cases; 13 fail today. Do not edit their expectations (they are Neovim's); make the engine match:
- Empty objects (`di"` on `""`, `dit` on `<a></a>`, `di(` on `()`, `di[` on `[]`): Neovim makes an empty undo entry, so a following `u` undoes that entry, not the previous change. The engine errors and makes none. (This is not F-1's rule: an empty object is a usable object; F-1's "no object, no change, no undo entry" stays for objects Vim cannot find. Keep those goldens passing.)
- Backward deletes (`dh` at column 0, `dh`/`db` from mid-line, `db` on an empty line and at a line start, `d0`): undo cursor and empty-entry behaviour as Neovim.
- Change start: after `cit`/`cat` over lines, `ciw` etc. followed by `u`, the cursor goes to the start of the change as Neovim does (the engine leaves it at the original position). `dit` then `.` then `u` likewise.
Find the common cause rather than patching case by case (the undo snapshot's cursor, and when an empty entry is recorded). Add any further goldens you need to pin the rule (generate them with Neovim).
