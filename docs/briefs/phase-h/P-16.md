## Why
Renzo: "the 'your new keys' page is poorly designed, it needs to be scrolled up/down to see the whole content + appears out of nowhere, needs some redesign, I like the idea tho."
What is wrong: a black page replaces the world with no lead-in; it lists up to three keys before any is needed; the examples are `abc` in a box, nothing like the game; and you only read.

## 1. When it appears
- A key's page opens right after the dialogue that first names that key (its backticked keycap in this stage's dialogue text, parsed with `keyParts`; commands like `5r=`, `10dd`, `"0p` name `r`, `dd`, `"`), as the continuation of that dialogue. A key named only in an objective or hint opens after the stage's intro dialogue, at most 2 of them; any others get no page (they are in `:help`, marked "new").
- At most 2 pages in a row. If one dialogue names more, the extra keys wait for the next dialogue that ends in this stage, or are dropped when the stage ends.
- Each key's page opens once per save: store seen keys in `localStorage` `unsaved.keys-seen.v1` (try/catch; blocked storage means session memory only). New game clears it. Replays, Continue and deaths never show a page again.
- Never over a dialogue, cutscene, clear card, script or death.

## 2. What it looks like
- The game stays visible, dimmed to about 45%. A notebook page (paper colour, ink text, a torn top edge in pixel steps, a small portrait of the Scribe in the corner) slides up from the bottom in 240 ms with the existing paper-rustle cue (no slide with reduced motion). It is clearly the same voice as the Scribe's notes: header "From the Scribe's notebook".
- One key per page. Width min(92vw, 560px); the whole page fits at 800x500 and 375x667 with no scrolling, ever (a test on the CSS contract: no `overflow: auto/scroll`, sizes in `clamp`/`vh`).
- Left: the keycap, large (64 px). Right: the one-line description (20 px). Below: the demo, full width. Footer: page dots if there are two, and the two controls.

## 3. Try it (the heart of it)
- The demo is a strip of real game tiles, not letters: 1 to 3 rows of the help entry's example drawn with a small canvas using the existing sprites (ground, rubble, water, plank, and generic letter tiles where the example needs letters), Tilde standing on the cursor cell. Use the world's palette.
- It first plays itself once: the keys appear under the strip one by one, then the result.
- Then it asks: "Your turn: press `x`." The player's keys drive a real engine instance (`@escape/engine`, created in the component, seeded from the example's `before`, only the keys of this example allowed). A correct key updates the strip; a wrong key shakes the prompt (no shake with reduced motion) and says which key is expected; finishing shows "That's it." and a tick.
- `Enter` continues at any time after the 300 ms guard ("Enter: got it" before trying, "Enter: on you go" after); `Esc` skips the remaining pages. When the example itself uses `<CR>` or `<Esc>`, that key goes to the demo first and continues only after it is finished.
- No key pressed while the page is open reaches the game, and held keys do not leak after it closes. F1 and browser shortcuts still work; `:help` open suspends the page (as `KeyCard` does today).
