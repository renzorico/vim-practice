# P-6: Show, don't tell; reward par (landing markers, blocked reasons, stage-clear card, stars)
Owns: `apps/game/src/**` (not the old `play/` and `ui/`). No change to `packages/**` or any content file.
Runner: codex. Reviewer: claude-sonnet, then a browser check by the design lead, then Renzo plays it.
Read `docs/briefs/phase-b/_common.md`, `apps/game/src/play2/PlayScreen.tsx`, `session.ts`, `progress.ts`, `apps/game/src/scene/FieldScene.ts` (P-4's movement code is on this branch: keep it), and the "Why" of `docs/briefs/phase-h/P-4.md`.

## Why
Renzo: "poor designed and explained". The game explains in dialogue boxes, then gives no feedback while you play: a blocked key looks like a dropped key, par is invisible, and clearing a stage just loads the next one. A player learns Vim by seeing where a key lands and by being shown a better route, not by reading.

## 1. Landing markers (the field shows what a key does)
- A stage's new keys are its `STAGE_COMMANDS` minus the previous stage's (in story order). Keep only motions (keys that move the cursor without changing text: `w b e W B E 0 ^ $ gg G { } % n N * # ; ,` and counted `hjkl` are not needed). Up to 4 per stage.
- Every turn, for each new key, run it on a copy of the current world state (the engine and the sim are pure; never touch the live session) and, if the cursor would move, draw the key's label in small type on the landing cell (`kbd` style, the World's palette, alpha 0.7; darkness rules apply: no marker in the dark beyond the light).
- Markers disappear for a key after the player has used it 3 times in this stage, and all markers hide while a command is pending or a dialogue is open. Reduced motion: still shown (they are not motion).
- Pending `f`/`t`/`F`/`T` + a character: the marker shows where that full command would land as soon as it is complete; not before.

## 2. Why a key did nothing
When a turn ends with a `bump` event or an engine error, the footer's pending-keys output shows a short reason for 1.5 s (in time, in `apps/game` only), then clears:
- `bump` reasons (see `BumpReason` in `packages/world/src/types.ts`): one plain line each, e.g. "Blocked: a wall.", "That stone is fixed: it can't be deleted.", "Nothing to undo." Cover every `BumpReason`; a test pins the list.
- Engine errors for search: Vim's text ("E486: Pattern not found: ink").
Never a tone of failure ("wrong", "oops"); just the fact.

## 3. Par in the HUD
`Turn 3 · par 5` (par = `stage.parTurns`). Past par, the par text dims; no other change.

## 4. Stage-clear card (every stage)
When a stage is cleared and its end presentations have played, before the next stage loads, show a card:
- "<Stage title> cleared" and stars: 3 at par or better, 2 up to `ceil(par * 1.5)`, 1 otherwise.
- "Turns: 9 · par 6" and hearts left.
- Below par or at par: "Par route found." Over par: "Par route: " then the stage's `solution` as key caps (group keys into commands as typed: `*` `w` `*` `w` `*` `e` `<CR>`; a search is one cap `/ink<CR>`).
- Buttons and keys: `Enter` continue, `r` replay this stage (restores `session.stageEntry`: the story and world as the stage began; nothing learned during the stage is lost: keep `learnedSkills` and `clearedStages` as `restoreCheckpoint` does).
- The best result per stage (fewest turns, stars) is saved: add an optional `best: Record<stageId, { turns: number; stars: 1|2|3 }>` to the progress save (`progress.ts` schema, strict; older saves without it still load: test).
- The last stage's existing ending and "To be continued" screens stay as they are; the card comes before them.

## 5. Title screen
Under Continue, show total stars ("Stars: 41 / 84") once any stage has a best.

## Tests
- Markers: for Lowlands' first stage, `w` and `e` markers land where `w`/`e` would (computed, compared with a real step); a key used 3 times loses its marker; markers do not change the session (same object identity before and after); none while a command is pending.
- Every `BumpReason` has a line; a search miss shows E486.
- HUD shows `par`.
- Card: stars thresholds (par, par+1, ceil(1.5 par), beyond); the solution rendered as caps for 3 stages (one with a search, one with `<CR>`, one with a count); `r` restores the stage entry and keeps learned skills; best is saved and only improves; an old save without `best` loads.
- The full-run App test still reaches the ending (press Enter on every card).
- `stageReplayIssue` passes for every stage.
