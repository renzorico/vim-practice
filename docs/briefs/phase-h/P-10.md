Rule from P-6: anything stored on the Session is multiplied by the solver's state count. Keep new state out of the Session (the save and React state only).

## Why
Stars and par only matter if you can go back. Today Continue resumes the furthest stage, and the only replay is `r` on the card right after a clear.

## 1. Saving stage entries
When a stage is entered for the first time, store its entry story in the save: `entries: Record<stageId, StoryState>` (optional in the strict schema; old saves load and simply have no entries for stages reached before this change). Never overwrite an entry once stored (the first arrival is the canonical start). A test: entering three stages stores three entries; re-entering does not change them; an old save loads.

## 2. The menu
Title menu: "Continue", "Stages", "New game", "Sound" (P-8). `Stages` opens a list grouped by world (world name as a heading, stages in story order): each row shows the stage title, its stars (or "-" when unscored: text stages and the Margin, see `isScoredStage`), and is selectable only if it has an entry. Keyboard: `j`/`k` move, `Enter` plays, `<Esc>` or `q` returns to the title. Mouse click works too. Locked rows are dimmed and skipped by `j`/`k`.
- Playing a stage from the list starts it from its stored entry story (with the current `learnedSkills` and `best` kept, as replay does) and, when it is cleared, the clear card's Enter returns to the Stages list (not to the next stage), unless that stage is the furthest reached: then Enter continues the story as usual.
- The furthest-reached progress (what Continue resumes) is never overwritten by playing an earlier stage.

## 3. Tests
- The list shows only reached stages as selectable; stars match `best`; unscored stages show "-".
- Playing an earlier stage and clearing it returns to Stages and leaves Continue's stage unchanged; best improves if better.
- Playing the furthest stage from the list behaves like Continue.
- `j`/`k` skip locked rows; `<Esc>` returns to the title; the full-run App test still reaches the ending.
- `glades-finalize` peak memory unchanged (no Session growth): report the number from `/usr/bin/time -l npx vitest run apps/game/src/play2/glades-finalize.test.ts` if your sandbox allows it.
