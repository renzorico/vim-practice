# P-12: `:help` (a reference for every key you have learned)
Owns: a new `apps/game/src/play2/help/**` (data, component, tests), `apps/game/src/play2/PlayScreen.tsx` and `apps/game/src/App.tsx` (only to open/close it and route keys), `apps/game/src/play2/play.css`. No change to `packages/**` or story content. Nothing on the Session (the solver keeps one per explored state): the overlay is React state.
Runner: codex. Reviewer: claude-sonnet, then a browser check by the design lead.
Read `docs/briefs/phase-b/_common.md`, `apps/game/src/play2/PlayScreen.tsx` (`learnedKeycaps`), `apps/game/src/play2/session.ts` (`STAGE_COMMANDS`, how command-line mode reaches the engine), `apps/game/src/input/` (key capture).

## Why
Renzo: "poorly explained". A key is taught once, in a dialogue box, and then it is a cap in the footer with no explanation. Vim's own answer is `:help`.

## 1. The reference data
`help/keys.ts`: one entry per key or command the game teaches (every command in any `STAGE_COMMANDS` list, `:w`, `:e!`, `:q`), each with: the key as typed, a plain one-line description (what you see happen, e.g. "`w` jumps to the start of the next word"), a tiny example (`before` and `after` buffer line with the cursor shown as `[x]`), and the world where it is taught. Plain words, no jargon beyond the key's own name; at most 60 characters per description. A test checks every taught command has an entry and every example's `after` is what the real engine produces from `before` (run it through `@escape/engine`).

## 2. Opening it
- In any stage, typing `:help<CR>` or `:h<CR>` opens the reference instead of sending the command to the engine (intercept in the app before the key reaches the session: the engine never sees it, no turn is spent). `F1` opens it too. A footer link "`:h` keys" opens it with the mouse.
- It lists only keys learned so far (the same source as the footer caps, plus `:w`/`:e!` once they are taught), grouped by world, newest world first, the current stage's new keys marked "new".
- `j`/`k` scroll, `/` filters by typing (Esc clears the filter), `q` or `<Esc>` closes and returns to the game exactly as it was (no key leaks into the game).
- From the title screen: a "Keys" item under Stages (shows keys learned in the saved game, or the first world's if none).

## Tests
Data coverage and engine-checked examples; `:help<CR>` and `:h<CR>` open it without a turn or engine change (session identity unchanged); `F1`; only learned keys listed; `q`/`<Esc>` close; `/` filter; title "Keys"; the full-run App test passes.
