## 1. Sim: `text` triggers
`{ on: 'text'; anchor: EntityId; text: string }`. At turn end (where `enter` triggers are checked, same order and the same `once`/`onlyIf`/`unless` rules), fire when the anchor entity exists and the `text.length` characters right after its cell on its row are exactly `text` (a row too short never matches). Never fires mid-command or on a bump. Schema: `anchor` must name an entity of the stage; `text` non-empty.
Tests: fires when `p` puts the matching text after the anchor; does not fire for a partial or longer-different match; follows the anchor when text is inserted or deleted before it on the row and when rows above are deleted; a removed anchor never fires; `once` holds; `u` that breaks the match does not "unfire" it.

## 2. Solver: operators, put, registers
Today `fieldActions` explores motions plus `x`, `r`, `dd`. When learned and allowed, add:
- `d` + each learned motion with counts (as motions do, saturating), including `t`/`f` + each character on the row; `dd` with counts already exists.
- `y` + the same motions, and `yy` with counts; `p` and `P` with counts 1..(row length), stopping when the result repeats.
- Registers: when `"` is learned, prefix `d`/`y`/`p`/`P` with each register in `"a "b "0` (only these three: enough for World 4, bounded search); `"0p` included.
- Identity must include the registers that the stage's commands can read (`"`, `0`, `a`, `b`), or two states with different yanked text would merge.
- Not `c`: field stages never take insert mode (WORLD-4 rule 3). If `c` is in the learned list, skip it in the field solver.
